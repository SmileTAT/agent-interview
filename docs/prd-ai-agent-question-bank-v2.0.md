## 三、产品概述

### 3.1 需求背景

2026 年 AI 岗位面试的重心已从「大模型基础八股」转向「AI 应用与 Agent 落地」。字节、腾讯、阿里、美团、快手及各 AI 初创公司在春招中普遍考察 Agent 系统设计与工程实战：设计企业级智能客服 Agent、工具调用失败的兜底策略、多 Agent 任务编排、Agent 评测方案等**生产级问题**，而不再停留于概念背诵。

与此同时，Agent 技术栈以月为单位演进（MCP、A2A 协议、Claude Agent SDK、OpenAI Agents SDK、LangGraph、Context Engineering、Agentic RL……），求职者面临三个痛点：

1. **知识点散**：面经散落在知乎/牛客/公众号，无体系；
2. **深度不够**：市面题库多为单问单答，无法应对面试官的 3~5 层递进追问；
3. **过时快**：静态题库跟不上协议与框架的迭代速度。

### 3.2 产品定位

**「面向 AI Agent 岗位的工程化面试题库」** —— 不是又一个八股合集，而是：

- 以 **Agent 能力主题**（规划、工具调用、记忆、多智能体、评测、安全）组织，而非按厂商组织；
- 以**面试真实形态**呈现：概念题 + 系统设计题 + 场景排错题 + **追问链**；
- 以**真实面经溯源 + 月度保鲜**保证内容可信与不过时。

### 3.3 目标用户

| 用户类型 | 描述 |
|---------|------|
| **求职者（核心）** | 目标岗位为 AI Agent 开发 / LLM 应用工程师 / AI 应用算法的候选人（含后端/算法转行者） |
| **面试官（次要）** | 需要按主题+难度+题型快速组卷的面试官 |
| **内容贡献者（社区）** | 分享真实面经、参与题目审校的从业者 |

### 3.4 核心价值

一句话：**让 Agent 岗求职者按真实面试的形态与深度进行准备**。

- **主题精准**：只做 Agent 全栈，不摊大饼到模型预训练/推理底层（相关内容仅作"交叉基础"标签保留）；
- **形态还原**：追问链还原面试官递进拷问；系统设计题附评分维度（rubric）；
- **可信可溯**：题目标注来源（公司+岗位+时间，脱敏）；
- **持续保鲜**：每题带"最近复核时间"，月度跟进协议/框架演进。

## 四、竞品分析与差异化（重写）

### 4.1 竞争格局（2026-07）

| 竞品 | 类型 | 覆盖情况 | 弱点（即我们的机会） |
|------|------|---------|---------------------|
| 小林面试笔记 | 付费题库 | 已系统覆盖 Agent/RAG/MCP/Context Engineering，图解丰富，月度更新 | 单问单答为主，追问深度与系统设计题占比低；无来源溯源 |
| 卡码笔记（kamacoder） | 免费题库 | Agent/RAG/Transformer/Vibe Coding 面经汇总 | 汇总性质，体系化与题型结构弱 |
| JavaGuide AI 版 | 免费文档 | AI 面试指南含 Agent/RAG | 面向 Java 转型人群，Agent 深度有限 |
| AgentGuide（GitHub 开源） | 开源指南 | LangGraph 实战 + 面试题 | 偏教程，非结构化题库，无筛选/搜索产品化 |
| 面试鸭 / 牛客 | 综合题库/社区 | 全方向，量大 | 不垂直，Agent 内容浅且混杂 |
| DataCamp / Interview Coder / igmGuru / Udemy（海外） | 英文题单/课程 | Agentic AI 30~500 题合集 | 英文、脱离国内大厂面试语境与面经 |

**结论**："做一个 Agent 垂直题库"本身已不是差异点（小林等已占位），差异必须建立在**题目形态、内容机制与可信度**上。

### 4.2 四大差异点

| # | 差异点 | 说明 | 竞品现状 |
|---|--------|------|---------|
| 1 | **追问链（Follow-up Chain）** | 每道核心题附 3~5 层面试官递进追问及应答思路（如：什么是 MCP？→ 和 Function Calling 什么关系？→ 服务端工具太多导致上下文膨胀怎么办？→ 如何做工具权限与安全边界？） | 竞品普遍单问单答 |
| 2 | **系统设计题 + 评分维度** | "设计一个 XX Agent"类题目附面试官视角的 rubric（需求澄清/架构/工具设计/记忆与上下文/评测/成本与降级），教用户"答到什么程度算好" | 竞品仅给参考架构，无评分视角 |
| 3 | **真实面经溯源** | 题目标注脱敏来源：`字节 · Agent 平台 · 2026Q1 二面`，按公司/时间可筛 | 竞品来源模糊或无标注 |
| 4 | **内容保鲜机制** | 每题含 `last_reviewed_at`，月度专项复查协议/框架类题目（MCP、A2A、SDK 版本），过期内容显式标记 | 竞品靠人肉整站更新，无题级时效管理 |

## 五、MVP 功能范围

### 5.1 MVP 核心原则

沿用 YAGNI。核心价值 = **让用户按主题/题型找到高质量 Agent 面试题并学到追问深度**。凡不直接服务该价值的功能一律后置。

### 5.2 功能清单

#### P0（MVP 必做）

| 功能模块 | 功能点 | 说明 |
|---------|--------|------|
| **题目浏览** | 按能力主题浏览 | Agent 基础 / 工具调用与 MCP / 上下文工程 / 记忆 / 多智能体 / Agentic RAG / 评测 / 安全护栏 / 框架实战 / 交叉基础 |
| | 按题目类型筛选 | 概念题 / 系统设计 / 场景排错 / 编码实现 / 开放讨论 |
| | 按难度筛选 | 初级 / 中级 / 高级 |
| | 题目列表展示 | 标题、类型、难度、主题标签、来源（公司+时间） |
| **题目详情** | 题目 + 参考答案 | Markdown 渲染；答案默认折叠（先思考后查看） |
| | **追问链展示** | 逐层折叠展开，还原面试递进 |
| | 系统设计题 rubric | 评分维度表格 |
| **搜索** | 全文关键词搜索 | 支持术语搜索（"MCP""ReAct""LangGraph""轨迹评测"） |
| **内容管理** | Git + Markdown 内容仓库 | 题目即 Markdown 文件（含 frontmatter 元数据），PR 审校流即内容质量机制；静态站构建发布。**不做后台 CRUD** |

#### P1（MVP 后快速迭代）

| 功能模块 | 功能点 | 说明 |
|---------|--------|------|
| 用户系统 | 注册/登录、收藏、刷题进度 | 基础账号体系 |
| 题目组织 | 学习路线（Roadmap） | "1 个月上岸路线：Agent 基础→工具调用→RAG→系统设计" |
| | 按公司筛选面经 | 基于溯源字段聚合 |
| 内容贡献 | 站内投稿入口 | 降低非技术贡献者门槛（P0 阶段用 GitHub PR） |
| 管理后台 | 题目 CRUD 后台 | 内容量 >300 或非技术编辑加入后再建 |

#### P2（暂不纳入）

- 在线代码执行 / 模拟面试（AI 面试官）/ 社区评论 / 移动端 App / 英文版

### 5.3 明确不做（MVP 排除项）

| 排除项 | 原因 |
|--------|------|
| 厂商模型架构专题（v1.1 主体） | 与 Agent 岗考察重心错位，维护成本高、过时快；仅保留与 Agent 相关的交叉基础 |
| 管理后台 | Git + Markdown + 静态站替代，省 1/3 开发量且自带版本/审校/协作 |
| 在线编程环境 | 编码题给参考实现即可 |
| 视频/音频、多语言 | 成本高，初期不做 |

## 六、信息架构

### 6.1 页面结构

```
├── 首页（主题入口 + 搜索框 + 最近更新）
├── 主题浏览页（十大主题，见 §7）
│   └── 筛选器：题目类型 / 难度 / 来源公司 / 框架标签
├── 题目详情页
│   ├── 题目内容 + 元信息（类型/难度/标签/来源/最近复核时间）
│   ├── 参考答案（默认折叠）
│   ├── 追问链（逐层折叠）
│   └── rubric（系统设计题）
├── 搜索页
└── 内容仓库（GitHub，题目源文件 + 贡献指南 + PR 审校流）
```

### 6.2 数据模型（题目 frontmatter / Question）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | STRING | 唯一标识（slug） |
| title | STRING | 题目标题 |
| content | TEXT(MD) | 题目描述 |
| answer | TEXT(MD) | 参考答案与解析 |
| follow_ups | LIST | 追问链：`[{question, answer}]`，3~5 层 |
| rubric | LIST | 评分维度（系统设计题）：`[{dimension, expectation}]` |
| topic | ENUM | 十大能力主题之一（主维度） |
| question_type | ENUM | concept / system_design / debugging / coding / open_discussion |
| difficulty | ENUM | junior / mid / senior |
| tags | LIST | 技术标签（如 ["MCP","LangGraph","ReAct"]） |
| frameworks | LIST | 相关框架/协议标签（可为空） |
| source | OBJECT | 溯源：`{company, role, round, date}`，可为空（原创题标 original） |
| last_reviewed_at | DATE | 最近复核时间（保鲜机制核心字段） |
| status | ENUM | draft / reviewed / stale |
| created_at / updated_at | DATE | 时间戳 |

> 设计要点：主维度为 `topic`（能力主题），公司仅存在于 `source`（溯源）与筛选标签中——修正 v1.1 以厂商为主维度的问题；所有字段英文命名——修正 v1.1 中文字段名问题。

## 七、题库内容框架（十大主题）

| # | 主题 | 核心考点 | 占比目标 |
|---|------|---------|---------|
| 1 | **Agent 基础与推理模式** | Agent 定义与 Workflow 区别、ReAct、Plan-and-Execute、Reflection/Self-Critique、推理模型（o系列/R1）在 Agent 中的作用 | 15% |
| 2 | **工具调用与 MCP** | Function Calling 原理与 schema 设计、工具错误处理与重试、MCP 架构（host/client/server）、工具过多的上下文管理、工具权限与安全 | 15% |
| 3 | **上下文工程（Context Engineering）** | 上下文窗口管理、压缩/摘要策略、KV Cache 与成本、prompt 结构设计、长任务的上下文接力 | 10% |
| 4 | **记忆系统** | 短期/长期记忆、记忆写入与检索策略、向量库 vs 结构化记忆、跨会话个性化 | 8% |
| 5 | **多智能体系统** | 编排模式（supervisor/swarm/层级）、A2A 协议、任务分解与结果聚合、通信成本与失控风险 | 10% |
| 6 | **Agentic RAG** | 传统 RAG vs Agentic RAG、检索规划与自适应检索、GraphRAG、引用与幻觉抑制 | 10% |
| 7 | **评测与可观测** | 轨迹级评测（trajectory evals）vs 结果评测、LLM-as-Judge、线上监控与回归集、A/B 与灰度 | 10% |
| 8 | **安全与护栏** | 提示注入与工具滥用、权限最小化、human-in-the-loop 设计、沙箱执行 | 7% |
| 9 | **框架与工程实战** | LangGraph / AutoGen / CrewAI / OpenAI Agents SDK / Claude Agent SDK 选型对比、状态机与 checkpoint、流式与中断恢复、部署与成本优化 | 10% |
| 10 | **交叉基础** | Transformer 要点、SFT/RLHF/DPO/GRPO 与 Agentic RL、微调 vs 提示工程 vs RAG 的选型、推理优化常识 | 5% |
| — | **系统设计真题专区**（跨主题） | 智能客服 Agent、代码助手、Deep Research、企业知识库问答、运维 Agent 等场景设计题（每题带 rubric） | — |

## 八、业务流程

### 8.1 用户刷题流程

```
进入首页 → 选主题/题型/搜索 → 浏览列表 → 进入详情 →
思考后展开答案 → 逐层展开追问链 → （P1）收藏/标记进度
```

### 8.2 内容生产流程（新增，替代 v1.1 后台录入）

```
选题（面经收集/前沿跟进）→ 撰写 Markdown（含 frontmatter/追问链/rubric）→
提交 PR → 双人审校（事实核查 + 来源核验）→ 合并即发布（CI 构建静态站）
                                    ↑
        月度保鲜巡检：扫描 last_reviewed_at > 90 天的协议/框架类题目 → 复核或标记 stale
```

> 该流程直接修复 v1.1 的两个缺陷：无审校机制（导致 CISPO/DSA 类事实错误）、无保鲜机制（导致 Claude 版本号类过时内容）。

## 九、非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 静态站，页面加载 < 1 秒；搜索响应 < 500ms（客户端索引） |
| 可用性 | 静态托管（Pages/CDN），可用性 ≥ 99.9% |
| 兼容性 | 主流浏览器 + 移动端浏览器自适应（无 App，但必须移动可读） |
| 内容质量 | 100% 题目经双人审校；来源可溯或标注原创 |
| 可扩展性 | frontmatter 模式支持新增主题/题型/字段，不破坏存量 |

## 十、数据指标（MVP 阶段）

**北极星指标：周有效学习用户数**（当周展开 ≥ 3 道题答案的用户）。

| 指标 | 目标值（上线 1 个月） | 对应验证的假设 |
|------|---------------------|---------------|
| 题库总量 | ≥ 120 道（质量优先于 v1.1 的 150） | 内容生产 SOP 可持续 |
| 追问链覆盖率 | 核心题 100% 带追问链 | 差异点 1 成立 |
| 系统设计题数量 | ≥ 15 道（全部带 rubric） | 差异点 2 成立 |
| 周有效学习用户 | ≥ 80 | 核心价值成立 |
| 答案展开率 | ≥ 60% | 题目质量与吸引力 |
| 平均阅读深度 | 追问链平均展开 ≥ 2 层 | 追问链被真实使用 |
| 外部贡献 PR | ≥ 5 个 | 社区共建模式可行 |

冷启动渠道（v1.1 缺失项）：GitHub 开源引流（README 即题目索引）+ 知乎/掘金专栏连载精选题 + 牛客面经区回链。

## 十一、MVP 版本规划

| 阶段 | 时间 | 内容 |
|------|------|------|
| Phase 0：内容准备 | Week 1-2 | 制定题目模板与审校 SOP；完成首批 60 道核心题（主题 1/2/6/7 优先），含 10 道系统设计题 |
| Phase 1：开发 | Week 2-3 | 静态站：主题浏览 + 筛选 + 详情（折叠答案/追问链/rubric）+ 客户端搜索 |
| Phase 2：上线 | Week 4 | 部署 + GitHub 仓库开源 + 冷启动内容分发 |
| Phase 3：验证与补量 | Week 5-8 | 补至 120 道；跑通月度保鲜巡检；验证北极星指标 |
| Phase 4：迭代 | Week 9+ | 按数据决定 P1 优先级（学习路线 vs 用户系统 vs 投稿入口） |

## 十二、附录：术语表（已修正 v1.1 错误）

| 术语 | 说明 |
|------|------|
| MCP | Model Context Protocol，Anthropic 提出的模型-工具连接开放标准 |
| A2A | Agent2Agent，Google 提出的智能体间通信协议 |
| ReAct | Reasoning + Acting，推理与行动交替的 Agent 范式（Yao et al.） |
| Context Engineering | 上下文工程：对进入模型上下文的信息进行选择、压缩与组织的工程实践 |
| Trajectory Evals | 轨迹评测：对 Agent 全过程（工具调用序列、中间决策）而非仅最终答案的评测 |
| LLM-as-Judge | 用大模型作为评审员对输出打分的评测方法 |
| GRPO | Group Relative Policy Optimization，DeepSeek 提出的强化学习算法 |
| CISPO | **MiniMax** 在 M1 中提出的强化学习算法（v1.1 误标为智谱，已修正） |
| DSA | DeepSeek Sparse Attention，**DeepSeek** 的稀疏注意力机制（v1.1 误标为智谱，已修正） |
| RLHF / DPO | 基于人类反馈的强化学习 / 直接偏好优化 |
| GraphRAG | 基于知识图谱结构的检索增强生成 |
| Human-in-the-loop | 人在回路：Agent 关键动作前引入人工确认的机制 |
