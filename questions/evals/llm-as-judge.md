# LLM-as-Judge 怎么设计才可信？已知偏差与校准方法

<QuestionMeta />

## 题目

用大模型给大模型的输出打分已成为评测标配，但 Judge 本身并不天然可信。请说明 Judge 的设计要点、已知偏差与校准方法。

::: details 参考答案

**设计要点**：

1. **rubric 具体化**：不要"给整体质量打 1-10 分"（分数没有锚定，批次间不可比），改为**可核对的检查项**——"是否解决了用户问题（是/否）""是否包含无依据的断言（列出）"，每项独立判定再汇总；
2. **选择合适的判定形态**：二元判定 > 少档分级 > 连续打分（可靠性递减）；对比场景用**成对比较**（A/B 哪个更好）而不是各自打绝对分——模型做相对判断远比绝对判断稳定；
3. **要求先分析后结论**：让 Judge 先逐项引用证据分析、最后给判定，既提升质量又留下可审计的理由；
4. **Judge 与被评者解耦**：评测提示中不携带生成时的系统提示立场，避免 Judge 顺着生成逻辑"自我辩护"。

**已知偏差清单**：位置偏差（成对比较偏向先出现的）、长度偏差（偏爱更长回答）、自我偏好（偏爱同源模型的风格）、风格压倒事实（流畅自信的错误答案得高分）、评分档位偏好（回避极端分）。

**校准方法（核心是"评测评测者"）**：

- 建**人工金标集**：抽样让人类专家判定，计算 Judge 与人类的一致率——这是 Judge 可用性的准入门槛，达不到就换模型/改 rubric；
- **对称化去位置偏差**：成对比较交换顺序跑两遍，不一致的记平局或送人工；
- **持续回测防漂移**：Judge 模型升级、rubric 修改后必须在金标集上回归；
- 高风险结论（发版决策）用 Judge 初筛 + 人工复核不一致样本的两级流程。

**答题关键**：rubric 检查项化、成对优于打分、偏差清单、金标集一致率作为 Judge 的准入与监控。

:::

## 追问链

::: details 追问 1：人工金标本身有分歧（专家也意见不一）怎么办？

先量化人类间一致率（IAA）——它是 Judge 一致率的天花板：人类都只有七成一致的任务，别要求 Judge 九成。分歧处理：细化标注指南消除定义模糊（大部分分歧源于标准不清而非真分歧）；真正主观的维度改成多标员投票或分布标注；有些维度（文风偏好）承认无金标，退出自动评测改用用户行为数据衡量。

:::

::: details 追问 2：用最强的模型当 Judge 评它自己（同一个模型生成+评审），结论可信吗？

要打折。自我偏好偏差在"同模型生成+评审"时最强，尤其在风格相关维度。缓解：事实性、完成度这类客观检查项受影响较小，可以用；风格与整体优劣的比较换异源 Judge 或人工；关键对比（模型选型、发版）用多个不同家族的 Judge 交叉验证，结论一致才采信。另外注意"评审能力≠生成能力"——弱一点的模型带好 rubric 做检查项判定，往往够用且便宜。

:::

::: details 追问 3：Judge 评"轨迹"（整个 Agent 执行过程）比评单条回答难在哪？

三点：**输入超长**——几十轮轨迹塞给 Judge，它自己也会 lost in the middle，需要先做轨迹的结构化摘要（步骤序列+关键决策点）再评，或分段评审后聚合；**评判维度更工程化**——工具选择合理性、路径效率这些需要领域知识，rubric 要给 Judge 足够的判断依据（如工具清单与用途说明）；**因果归因难**——"第 3 步的错误导致第 9 步失败"这类链式判断 Judge 容易出错，重要归因仍需人工。所以轨迹评测中"规则断言（确定性检查）+ Judge（开放判断）"的配比里，规则应占更大比重。

:::
