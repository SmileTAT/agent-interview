# 设计企业知识库问答系统（带权限的 RAG 问答）

<QuestionMeta />

## 题目

为一家中大型企业设计内部知识问答系统：知识散落在 Wiki、网盘文档、IM 群公告等多处，员工按部门/职级有不同的文档权限。要求答案可溯源。

::: details 参考答案（作答框架）

**1. 需求澄清**：知识源清单与规模？权限模型的现状（各源自己的 ACL 还是统一 IAM）？更新频率？问答的准确率要求 vs 可用性要求（答不出 vs 答错的相对代价）？

**2. 架构：连接器 → 统一索引 → 检索问答 → 溯源展示**

- **接入层**：各知识源的连接器（增量同步文档+**它的 ACL 元数据**），统一到内部文档模型（内容+权限主体+时效+来源）；
- **索引层**：结构感知分块（Wiki 按标题层级、表格整块）+ 混合索引（BM25+向量）+ 元数据（部门、时间、密级、原始 ACL）；
- **检索层**：**权限过滤在检索时硬性执行**（pre-filter：候选集先按提问者身份过滤，再做语义排序）——这是本题的第一考点，绝不能"检回来再让模型别说"；
- **生成层**：grounded 生成（仅基于检索内容、逐段引用、检索不足时明确说查不到+推荐可能知道的人/入口）；
- **展示层**：引用可点击跳原文（用户在原系统中无权的文档，引用也不可见）。

**3. 关键设计点**

- **权限的双重校验**：检索时过滤 + 返回前按最新 ACL 复核（防索引里的权限快照过期——文档权限变更与索引同步存在时间差）；
- **知识时效**：答案标注来源文档的更新时间；冲突文档按时效与权威源裁决（HR 政策以 HR 官方空间为准的源优先级配置）；
- **反馈闭环**：答案有用/没用的反馈回流；高频"查不到"的问题聚类后反哺知识建设（这是产品价值的隐藏一半——发现知识缺口）。

**4. 评测与指标**：检索层（标注集 recall/precision）+ 端到端（抽样人工评审：正确/部分正确/错误/正确地拒答）+ **越权检出必须为零**（红队用例：低权限账号问高密级内容）。北极星：问题解决率（用户无需再问人）。

:::

## 评分维度（rubric）

| 维度 | 合格 | 优秀 |
|------|------|------|
| 权限设计 | 知道要过滤 | pre-filter 硬过滤+ACL 时效复核+越权零容忍评测 |
| 数据接入 | 提到多源同步 | ACL 随文档同步、增量更新、统一文档模型 |
| 检索质量 | 用了向量检索 | 混合检索+结构感知分块+元数据过滤的组合 |
| 幻觉控制 | 提到引用 | grounded 约束+拒答路径+冲突裁决规则 |
| 产品闭环 | 有用户反馈 | "查不到"聚类反哺知识建设的飞轮 |
| 评测 | 有准确率指标 | 分层评测+把"正确地拒答"纳入正向指标 |

## 追问链

::: details 追问 1：各知识源的权限模型五花八门（Wiki 按空间、网盘按文件夹、IM 按群成员），统一权限怎么做？

不强行统一语义，统一到"**主体能否读该文档**"这个最终判定：连接器同步时把各源 ACL 解析为文档级的允许主体列表（用户/组），映射到公司统一身份（SSO/IAM 的组织架构）；解析不了的宁可标为"仅原系统可见"不入检索。权限变更靠**短同步周期+返回前实时复核**双保险。要向面试官主动指出：权限映射错误的方向性要求是"宁可漏答，不可越权"。

:::

::: details 追问 2：员工反馈"明明有文档就是搜不到"，排查路径是什么？

标准分层排查：文档进没进索引（连接器覆盖/同步失败/被权限标记排除）→ 分块是否合理（答案在表格/附件里被切碎或没解析）→ 检索没召回（术语不匹配：员工用黑话、文档用官方名——上同义词典/查询扩展）→ 召回了但排序沉底（重排调优）→ 生成阶段没用上（上下文太挤）。运营侧建"搜不到报告"一键反馈通道，每例都能归因到上述某层，形成检索质量的持续迭代机制。

:::
