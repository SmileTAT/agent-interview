# 设计一个运维值班 Agent（告警诊断与辅助处置）

<QuestionMeta />

## 题目

设计一个 SRE 值班 Agent：接收监控告警，自动收集证据、诊断根因、给出处置建议；低风险缓解措施可自动执行，高风险操作辅助人类执行。

::: details 参考答案（作答框架）

**1. 需求澄清**：接入的监控/日志/trace 系统？历史故障知识（runbook、复盘文档）的沉淀程度？"低风险可自动执行"的边界谁定义？误操作的最大可容忍代价？

**2. 核心架构：证据收集 → 诊断 → 分级处置**

```
告警触发 → 上下文富集（自动拉取：相关指标曲线、日志、trace、
           近期变更/发布记录、拓扑依赖、同期其他告警）
        → 诊断 Agent（假设生成 → 逐一验证 → 根因结论+置信度）
        → 处置分级：
           只读缓解建议 → 展示给值班人
           预授权剧本内的低危操作（重启单实例、扩容）→ 自动执行+通知
           高危操作（回滚、切流、改配置）→ 生成方案，人一键批准执行
```

**3. 关键设计点**

- **诊断即假设检验**：让 Agent 显式列假设清单（发布引入？依赖故障？容量？），逐个用工具取证验证——比"一步到位猜根因"可靠且过程可审计；**近期变更关联**是根因命中率最高的一条线索，必须重点建设；
- **工具分级（本题的安全核心）**：只读观测类工具全开放；变更类工具白名单+预授权剧本（人提前审定的标准处置，Agent 只能按剧本参数范围执行）；剧本外的变更一律只出方案不执行；
- **半夜无人策略**：可等待的挂起，时效敏感的执行保守缓解（扩容优于重启，重启优于回滚）+ 升级呼叫；
- **知识飞轮**：每次故障的诊断轨迹+人类最终处置回流为案例库，检索式注入后续同类告警（情景记忆的典型应用）；复盘文档结构化为新剧本。

**4. 评测**：历史故障回放集（脱敏的真实告警现场）测根因命中率与证据质量；处置类用演练环境（chaos 注入故障）验证；线上盯 MTTR 改善、误操作数（必须零）、值班人采纳率。

:::

## 评分维度（rubric）

| 维度 | 合格 | 优秀 |
|------|------|------|
| 诊断方法 | 收集日志给模型看 | 假设检验式诊断+变更关联优先+置信度输出 |
| 操作安全 | 高危要人批 | 预授权剧本机制+剧本外零执行+审计 |
| 证据工程 | 列了要接的数据源 | 自动富集的编排（拓扑关联、同期告警聚合） |
| 无人值守 | 提到升级呼叫 | 分时段自主度策略+保守动作优先级 |
| 知识沉淀 | 提到 runbook | 诊断轨迹回流案例库的飞轮设计 |
| 评测 | 有准确率概念 | 故障回放集+演练环境+误操作零容忍 |

## 追问链

::: details 追问 1：告警风暴（一次故障触发几百条告警）时 Agent 会怎么样？怎么设计？

不设计的话会被打爆（几百个并发诊断任务互相踩踏、烧钱且产出重复结论）。方案：诊断前置**告警聚合层**——按时间窗、拓扑关联、指标相似度聚类成"事件"，一个事件一个诊断任务；诊断 Agent 把"多告警共因"作为首要假设（风暴通常是单根因的辐射）；并发与预算护栏兜底。这题考察的是把 Agent 放进真实工程环境时的流控思维。

:::

::: details 追问 2：Agent 诊断错了根因，值班人按建议操作导致故障扩大，责任怎么算？设计上怎么降低这种风险？

设计要点：输出形态强制为"结论+置信度+**支撑证据链**+反证检查"——值班人核验的是证据而不是结论本身，界面上证据一键可达；低置信度结论显式声明并给出多假设并列；高危操作的方案附"如果诊断错误的回退路径"。流程上明确 Agent 定位是辅助（建议权）而人保留决策权，同时用采纳后结果的追踪数据持续校准置信度。责任框架清晰（人决策、系统辅助、证据留痕）本身就是采纳率的前提。

:::
