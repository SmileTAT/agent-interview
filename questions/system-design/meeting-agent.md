# 设计一个会议纪要与行动项跟踪 Agent

<QuestionMeta />

## 题目

设计一个会议 Agent：接入线上会议，生成结构化纪要，提取行动项（谁、做什么、何时），同步到任务系统并跟踪闭环。

::: details 参考答案（作答框架）

**1. 需求澄清**：会议类型分布（站会/评审/客户会——纪要模板差异大）？转写基建（自有 ASR 还是会议平台 API）？行动项写入哪个任务系统？隐私边界（哪些会议不许记录、录音保留策略）？

**2. 架构：转写 → 结构化理解 → 行动项抽取 → 系统集成 → 闭环跟踪**

- **转写层**：ASR+说话人分离（diarization）是上游地基——**行动项的"谁"字段依赖说话人识别**，这层的错误会级联；专有名词（人名、项目名）用企业词表热词增强；
- **纪要生成**：长会议超上下文 → 分段摘要+全局综合的层级式处理；按会议类型套模板（决策/讨论/待办分区）；**区分"决定了的"和"讨论过的"**——把讨论误写成决策是纪要最伤的错误；
- **行动项抽取**：结构化输出（负责人/内容/期限/来源发言片段），三个字段都要**带溯源**（点击可跳转到原文位置）；负责人与期限模糊的（"回头看一下"）标记为待确认而不是猜；
- **确认环节（关键设计）**：纪要与行动项先发给主持人/当事人**确认后**才写入任务系统——错误的任务分配比没有任务更糟，这一步 HITL 不能省；
- **闭环跟踪**：写入任务系统后跟踪状态，会前自动生成"上次行动项进展"注入下次会议——这个飞轮是产品价值的放大器。

**3. 隐私与合规**：录制知情同意（入会提示）；敏感会议（HR/法务）可豁免；录音与转写的保留期限与访问控制；纪要分发范围默认仅与会者。

**4. 评测**：纪要质量人工评审（关键信息覆盖率、决策/讨论区分正确率）；行动项抽取的 P/R（对照人工标注）；说话人归属准确率；产品指标：确认环节的修改率（越低说明质量越高）、行动项按期完成率变化。

:::

## 评分维度（rubric）

| 维度 | 合格 | 优秀 |
|------|------|------|
| 上游依赖 | 提到转写 | 说话人分离对行动项的级联影响+热词增强 |
| 纪要质量 | 能生成摘要 | 长会分段策略+决策/讨论的区分意识 |
| 行动项设计 | 抽取三要素 | 逐项溯源+模糊项待确认而非猜测 |
| HITL | 直接写任务系统（扣分） | 确认后写入+修改率作为质量指标 |
| 隐私合规 | 没提（不合格） | 知情同意+保留策略+分发边界 |
| 闭环价值 | 生成完就结束 | 跟踪+下次会前回顾的飞轮 |

## 追问链

::: details 追问 1：转写错误率较高（专有名词、多人抢话），下游全跟着错，怎么治理？

分层治理：转写层——企业词表热词、按会议室/设备优化音频质量、抢话段落标记低置信；理解层——让模型**结合上下文纠错转写**（"按语境这里应是项目名 X"）但纠错要标注；产品层——低置信片段在纪要中显示原音频跳转链接，确认环节引导当事人重点核对；度量层——建立转写 WER 与下游行动项准确率的关联监控，确定投入优先级。要点是承认上游不完美，让不确定性可见并可核验，而不是让下游装作输入是对的。

:::

::: details 追问 2：这个产品的价值怎么衡量？"纪要生成了"不等于"有用"。

分三层漏斗式指标：**质量层**——确认环节修改率、行动项抽取准确率（基础）；**行为层**——纪要打开/引用率、行动项在任务系统的认领率（有没有被当真）；**结果层**——行动项按期完成率的前后对比、"上次说过但没人跟进"类问题的减少（这是买单理由）。反指标也要盯：会议时长是否因"反正有纪要"而变长、行动项是否被滥发（每会 20 条没人看）。价值主张最终是"决议不落空"，指标要能支撑这句话。

:::
