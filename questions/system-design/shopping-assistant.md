# 设计一个电商导购 Agent

<QuestionMeta />

## 题目

为电商平台设计对话式导购 Agent：理解模糊需求（"送丈母娘的生日礼物，预算五百左右"），多轮引导，推荐商品，支持比价与下单协助。

::: details 参考答案（作答框架）

**1. 需求澄清**：接入的商品/库存/价格系统？推荐是否要与现有推荐系统协同（而不是绕开）？转化指标怎么定义？合规约束（价格宣传、竞品对比话术）？

**2. 架构：需求理解 → 引导式收敛 → 检索推荐 → 转化协助**

- **需求结构化**：把模糊表达解析为结构化需求（对象、场景、预算、偏好、禁忌），缺关键槽位时**引导式提问**（一次问一个最有信息量的问题，别像填表）；
- **商品检索**：结构化过滤（品类/价格/库存）+ 语义匹配（"显气质"这类软需求）走混合检索；**实时性硬约束**——价格库存必须实时查询工具，绝不能出自模型记忆或过期索引（报错价是事故）；
- **推荐生成**：候选 → 多样性策略（不同价位/风格 2~3 个）→ **推荐理由生成必须 grounded 于商品真实属性**（防"编造卖点"——面料成分、功效宣称错了是合规问题）；
- **转化协助**：优惠计算（用确定性的规则工具算，不让模型心算）、加购/下单走标准交易流程（Agent 只协助到收银台，支付环节回归经过验证的交易链路）；
- **记忆**：会话内偏好累积（说过不要红色就别再推）+ 跨会话轻量画像（尺码、常购品类，遵守隐私边界）。

**3. 关键护栏**：宣传合规词表校验（输出层过滤极限词/未授权功效）；比价与竞品话术的合规规则；不确定的商品参数宁可说"以详情页为准"。

**4. 评测与指标**：推荐相关性人工评审、卖点事实性抽查（对照商品详情）、价格准确率（必须≈100%）；业务北极星：导购会话转化率与客单价，对照组为无 Agent 的自然转化。

:::

## 评分维度（rubric）

| 维度 | 合格 | 优秀 |
|------|------|------|
| 需求理解 | 提到多轮追问 | 结构化槽位+最大信息量的引导策略 |
| 数据实时性 | 提到查库存 | 价格库存实时工具化+"不出自模型记忆"的明确原则 |
| 推荐质量 | 能出推荐 | 多样性策略+理由 grounded 于真实属性 |
| 合规意识 | 没提（不合格）/提到广告法 | 词表校验+功效宣称防线+价格准确率指标 |
| 交易边界 | Agent 全程包办 | 支付回归标准交易链路的边界意识 |
| 业务指标 | 有转化概念 | 转化率+对照组设计+客诉监控 |

## 追问链

::: details 追问 1：导购 Agent 和平台已有的推荐系统是什么关系？会打架吗？

正确定位是**协同**：推荐系统有海量行为数据训出的排序能力，Agent 的增量是"对话式需求表达"——把对话解析出的结构化需求作为推荐系统的实时特征/过滤条件传入，召回排序仍复用推荐系统，Agent 负责最后的呈现与解释。绕开推荐系统自建一套（纯靠语义检索排序）通常效果更差且浪费已有资产。打架的典型场景是目标不一致（推荐系统优化 GMV、Agent 优化"帮用户"），要在排序目标上显式对齐并留出"用户利益优先"的干预规则（如实说出缺货、不硬推高佣金商品——长期信任 vs 短期转化的经典权衡）。

:::

::: details 追问 2：用户问"这个和某某平台上那款哪个好"，怎么处理竞品对比？

三层处理：**事实层**可以做——本平台商品的参数如实对比；**跨平台层**谨慎——竞品的实时价格与参数你没有可靠数据源，基于过期或传闻数据的对比既误导又有法律风险，如实说明"无法获取对方实时信息"；**话术层**合规——贬损竞品是广告法红线，输出过滤要覆盖。产品上可以把这个场景转化为价值：聚焦讲清自家商品的差异化与适配度（"您提到的需求 X，这款的对应能力是…"），比不可靠的对比表更有说服力。

:::
