# 设计一个 Deep Research（深度调研）Agent

<QuestionMeta />

## 题目

设计一个深度调研 Agent：用户给一个研究问题（如"评估 X 行业未来三年的竞争格局"），Agent 自主进行多轮网络检索与阅读，产出带引用的结构化研究报告。要求支持 10 分钟以上的长任务。

::: details 参考答案（作答框架）

**1. 需求澄清**：报告的深度/篇幅预期？延迟容忍（分钟级异步可接受吗）？信息源范围（公开网络/内部库/付费源）？引用严格度？单次成本预算？

**2. 核心架构：规划-执行-综合三段式 + 子 Agent 并行**

```
研究问题 → 规划器（拆解为子问题树、确定调研策略，强推理模型）
        → 并行子 Agent × N（每个负责一个子问题：搜索→筛选→精读→结构化笔记）
        → 汇总综合器（跨子问题去重、冲突消解、缺口识别）
        →（不足则二轮补充调研：缺口反馈给规划器）
        → 报告生成（结构化写作+逐段引用）
```

- 子 Agent 并行是该场景的天然选择：子问题互相独立、过程 token 巨大而结论紧凑（上下文隔离收益最大化）；
- **迭代深化**而非一次穷尽：先广度扫描再对高价值方向加深，模仿人类调研节奏。

**3. 关键设计点**

- **上下文管理**：子 Agent 产出结构化笔记（结论+证据+来源+置信度）落共享存储，主上下文只持有笔记索引与摘要——报告生成时按章节拉取相关笔记；
- **信源质量**：来源分级（官方/权威媒体/论坛），交叉验证关键事实（单源结论标注），记录检索时间（信息时效）；
- **长任务工程**：阶段化 checkpoint（规划完成/各子问题完成/综合完成），可断点续跑；向用户流式汇报进度（正在调研什么），支持中途插入引导（"重点看看东南亚市场"）；
- **成本控制**：子 Agent 步数预算+全局 token 预算；广度阶段用小模型筛选，精读与综合用强模型。

**4. 评测**：报告事实准确率（抽查引用支持度）、覆盖度（对照专家清单）、引用有效率（链接可达且支持论述）、成本与时长分布。

:::

## 评分维度（rubric）

| 维度 | 合格 | 优秀 |
|------|------|------|
| 架构分解 | 有规划-执行-综合的分段 | 说清子 Agent 并行的理由（上下文隔离+独立性），有迭代深化机制 |
| 上下文策略 | 意识到长任务上下文会爆 | 笔记外置+索引拉取的完整方案 |
| 信息质量 | 提到引用 | 信源分级、交叉验证、时效标注成体系 |
| 长任务工程 | 提到异步 | checkpoint 恢复、进度流式、中途引导三件套 |
| 成本意识 | 提到预算上限 | 分阶段模型分级+预算矩阵 |
| 评测 | 有质量指标 | 引用支持度抽查等可落地的验证方案 |

## 追问链

::: details 追问 1：两个子 Agent 对同一事实给出矛盾结论，综合阶段怎么办？

综合器的冲突协议：并列呈现+按信源等级与时效裁决倾向+标注分歧；无法裁决的列入"待确认清单"触发定向补充调研（针对该事实的第三轮检索）。关键是**报告如实呈现不确定性**（"两种口径分别为X/Y，差异可能源于统计口径"）比强行给一个数可信得多——这也是对抗"报告看起来很确定其实是幻觉"的机制。

:::

::: details 追问 2：怎么防止调研 Agent 被网络上的 SEO 垃圾和内容农场污染？

检索层：域名信誉分级与黑名单、同模板批量内容的模式识别、优先结构化权威源（财报、统计局、论文库）；阅读层：单页结论必须多源印证才能进入"事实"级笔记，仅单源的降级为"待证"；另外内容农场常是间接注入的载体，阅读子 Agent 应是无敏感权限的低权 Agent（注入防御的架构化）。评测集中加入"污染场景"用例验证鲁棒性。

:::
