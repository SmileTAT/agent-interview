# 多 Agent 系统有哪些典型失败模式？怎么调试？

<QuestionMeta />

## 题目

你接手了一个质量不稳定的多 Agent 系统（supervisor + 5 个 worker）。请列举这类系统的典型失败模式，并给出系统化的调试方法。

::: details 参考答案

**典型失败模式（按层次）**：

**协作层**（多 Agent 特有，最该先查）：

1. **交接丢失**：约束没传下去 / 结论证据没带回来（占多 Agent 故障的大头）；
2. **重复劳动与空转**：两个 worker 做了同一件事；supervisor 反复委托同一任务因为"对结果不满意"却不说哪里不满意；
3. **踢皮球/委托循环**：任务在 Agent 间流转无人收敛；
4. **错误级联**：上游 worker 的错误结论被下游当事实使用，最终产出错误但每个环节"局部合理"；
5. **角色越界**：worker 超出职责范围行动（评审者顺手改了内容），破坏流程假设。

**个体层**（单 Agent 的老问题在每个成员身上都可能发生）：死循环、幻觉、格式错误——但在多 Agent 里被放大且更难定位。

**系统化调试方法**：

1. **先建全链路 trace**：一个任务一个 trace ID 贯穿所有 Agent，树状展示委托关系、每个 Agent 的完整轨迹、Agent 间消息原文。没有这个，多 Agent 调试就是盲人摸象；
2. **二分定位**：先判断"错误产生于哪个 Agent 内部"还是"产生于交接"——检查交接消息：下发的任务描述是否完备（对照约束清单）、返回的结论是否忠实于该 worker 的实际过程；
3. **单体复测**：把可疑 worker 拿出来，用交接消息中的原始任务单独重放——单体正常则问题在交接或编排，单体也错则是个体问题；
4. **修复优先级**：先修交接契约（结构化模板，收益最大），再修个体提示，最后才考虑改架构。

**答题关键**：协作层失败模式的枚举（交接丢失是头号）+ trace 先行 + 二分定位 + 单体重放。

:::

## 追问链

::: details 追问 1：错误级联怎么防？下游没法验证上游的每个结论吧？

不求全验证，抓三个杠杆：**关键结论带证据**——交接 schema 强制"结论+证据+置信度"，下游对低置信度结论触发抽查；**事实与推断分离**——worker 返回中区分"查到的事实"和"我的推断"，下游对推断保持怀疑；**汇聚点校验**——在 supervisor 汇总处做一次一致性检查（多个 worker 的结论互相矛盾时不要静默择一，显式复核）。级联的根源是"转述即事实化"，标注信息的确定性等级就能压住大半。

:::

::: details 追问 2：多 Agent 系统的回归测试怎么做？每次全链路跑太贵了。

分层测试金字塔：**个体层**——每个 worker 有自己的评测集（用真实交接消息做输入），独立回归，便宜且能覆盖大多数改动；**交接层**——mock worker，只测 supervisor 的任务拆解与汇总逻辑；**全链路层**——少量端到端冒烟用例（核心场景+历史事故回归），发版必跑。改动影响面决定跑哪层：改单个 worker 提示只需该 worker 评测+冒烟，改交接 schema 才全量。

:::

::: details 追问 3：系统不稳定但每次失败的样子都不一样，从哪里下手？

"每次都不一样"通常意味着**方差问题**而非单点 bug：先跑同一任务 N 次收集失败分布，聚类失败模式——常见发现是 80% 的杂乱失败最终归因到一两个上游源头（如 supervisor 的任务拆解不稳定，下游全跟着乱）。治理顺序：先降上游方差（拆解步换更强模型/加结构化约束/给 few-shot），上游稳定后下游失败往往自然收敛。多 Agent 系统的方差是乘法叠加的，投资该投在最上游。

:::
