# GRPO 与 PPO、DPO 的区别是什么？为什么 R1 选择 GRPO？

<QuestionMeta />

## 题目

面经高频题，二面有被要求手写公式的报告：对比 GRPO 与 PPO、DPO 的机制差异，并解释 DeepSeek 在 R1 训练中选择 GRPO 的动机。

::: details 参考答案

**PPO（RLHF 的经典选择）**：策略梯度方法，用裁剪的重要性采样比控制更新步长。关键负担在**优势估计**：需要一个与策略同规模的**价值网络（critic）**来估计基线，训练时要同时维护策略、价值、奖励、参考四个模型——显存、算力、调参复杂度都高，价值函数在长序列 token 级信用分配上也训得不稳。

**GRPO（DeepSeek 提出，DeepSeekMath/R1 使用）**：核心改动是**用组内相对比较替代价值网络**——对同一个提示采样一组（G 个）回答，各自打分后，以组内奖励的标准化值（减组均值、除组标准差）作为该回答的优势：

```
A_i = (r_i − mean(r_1..r_G)) / std(r_1..r_G)
```

目标函数保留 PPO 式的裁剪比率结构，并直接加 KL 正则项（相对参考策略）。**去掉 critic** 后：省一半模型显存、少一个不稳定的训练部件；"同题多答比相对好坏"天然契合推理任务——同一道数学题采样多条解答，对错立判，组内相对信号干净。

**DPO（对比项）**：不是在线 RL——跳过奖励模型与采样循环，直接在静态偏好对上用闭式损失优化。简单稳定，但无法在训练中探索新行为，能力上限受限于离线数据。

**为什么 R1 用 GRPO**：R1 的场景是**可验证奖励（RLVR）**——数学答案对错、代码测试通过，规则即可打分，连奖励模型都可省略；要在大规模长思维链上做在线 RL，去掉 critic 的工程节省是决定性的；组采样与"多样解题路径中强化更优路径"的目标天然匹配，R1-Zero 的推理能力"自我进化"（思维链越来越长、出现反思行为）正是建立在这个循环上。

**答题关键**：三者定位（在线带 critic / 在线去 critic / 离线）+ 组相对优势公式 + "为什么契合可验证推理任务"的动机链。

:::

## 追问链

::: details 追问 1（面经真实追问方向）：GRPO 用组均值当基线，相比 critic 的价值估计，牺牲了什么？

牺牲了**token 级信用分配**：critic 理论上能对序列中每个位置估计价值（哪几步推理是关键贡献），GRPO 的组相对优势是**整条回答一个标量**，均匀摊到所有 token——好回答里的废话步骤同样被强化。此外组内基线的方差依赖组大小 G（太小则噪声大，太大则采样贵）。在结果可验证、答案边界清晰的任务上这个牺牲可接受；在过程质量重要、奖励稠密的场景，critic 或过程奖励模型（PRM）仍有价值。

:::

::: details 追问 2：R1-Zero 和 R1 的奖励分别是怎么设计的？为什么不用神经奖励模型？

R1-Zero：纯规则奖励——**准确性奖励**（数学答案精确匹配、代码跑测试）+ **格式奖励**（思考过程置于指定标签内）。不用神经奖励模型的显式理由是**防 reward hacking**：大规模 RL 下策略会找到打分模型的漏洞刷分，规则奖励不可讨好。R1 在此之上增加了**语言一致性奖励**（治理 R1-Zero 思维链中的中英混杂）等；非推理类数据（写作、事实问答）在后续阶段仍用奖励模型捕捉人类偏好——两类信号按任务性质分工。

:::

::: details 追问 3：如果奖励只看最终答案对错，模型会不会学出"猜答案"或冗长堆砌的思维链？

会有这类倾向，这正是 RLVR 的已知边界：**答案碰对但过程错误**的样本会被强化（数学选择/数值题上概率不低）；思维链长度会自然增长，其中混有真反思与无效反刍。缓解手段：题目设计上偏好答案空间大的题（猜对概率低）、要求出示可验证的中间步骤、蒸馏/SFT 阶段用拒绝采样只保留过程与答案俱佳的轨迹（R1 第三阶段正是这么做的）、对长度做适度正则。这一问考察对"可验证奖励不等于万能奖励"的批判性理解。

:::
