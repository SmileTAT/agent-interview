# DeepSeek 是怎么把上下文扩到 128K 的？讲讲 YaRN 与长上下文扩展

<QuestionMeta />

## 题目

面经报告的考点：为什么 RoPE 不能直接外推到更长序列？YaRN 的原理是什么？V3 的长上下文扩展流程是怎样的？

::: details 参考答案

**问题根源：RoPE 的外推失效。** RoPE 用不同频率的旋转编码相对位置，模型只在训练长度（如 4K）内见过这些旋转角的组合。推理时序列超长，高频维度的旋转角进入训练没见过的区间，注意力分数分布崩坏——直接外推困惑度爆炸。

**朴素方案与缺陷**：

- **位置插值（PI）**：把位置索引线性压缩回训练范围（除以扩展倍数 s）。能用，但**所有频率一起压**——高频维度本来负责精细的邻近位置分辨，被压缩后局部分辨率受损，短距离建模变差，且需要可观微调；
- **NTK-aware 缩放**：改基频而非位置，高频少压、低频多压——保住局部分辨率。

**YaRN 的方案**（V2/V3 采用的扩展方法）：按维度频率**分段处理**——

1. 高频维度（波长远小于训练长度，负责局部关系）：**不插值**，保持原样；
2. 低频维度（波长接近或超过训练长度，负责远程关系）：**完全插值**（压缩进训练范围）；
3. 中间维度：两者线性过渡（ramp 函数）；
4. 额外对注意力 logits 乘一个随扩展倍数变化的**温度缩放**，修正长序列下注意力分布的熵漂移。

结果：用少量长文本继续训练即可高质量扩展，远省于从头训长上下文。

**V3 的落地流程**：预训练（4K）完成后，用 YaRN 做**两阶段扩展**——先扩到 32K 再扩到 128K，每阶段各约 1000 步的继续训练。分阶段的动机：逐步适应，比一步跨到 128K 更稳，且长文本训练的算力开销（注意力平方项）按需分配。

**答题关键**：RoPE 外推失效的机理 → PI 的"一刀切"缺陷 → YaRN 按频率分治 + 温度修正 → V3 两阶段流程。能把"高频管局部、低频管远程"讲清楚是关键。

:::

## 追问链

::: details 追问 1（面经真实追问方向）：怎么验证长上下文扩展是"真的能用"而不只是不报错？

分层验证：**困惑度**在目标长度上平稳只是底线；**检索类测试**（NIAH 大海捞针及多针变体）验证远程信息可访问；**更硬的任务级评测**——长文档问答、跨段落推理、代码仓库级任务，因为大海捞针满分但复杂长程推理拉胯是常见现象；还要**回归短上下文能力**（扩展不应损伤短序列表现，这正是 YaRN 保高频的动机）。V3 报告即用 NIAH 展示 128K 内表现稳定。

:::

::: details 追问 2：长上下文对推理服务的成本影响在哪？128K 是"免费"的吗？

完全不免费：**预填充**计算随长度平方增长，128K 请求的首 token 延迟以十秒计；**KV Cache** 随长度线性增长，挤占并发（这正是 MLA 压缩的价值放大点——两者是配套设计）；调度上长短请求混布会互相拖累（长请求的 prefill 阻塞短请求），需要分池或 chunked prefill。所以生产上"支持 128K"与"鼓励用 128K"是两回事，产品层仍应做检索与上下文管理，把长窗口当兜底而非默认。

:::

::: details 追问 3：除了改 RoPE，还有哪些长上下文技术路线？各自的定位？

四条主线：**位置编码扩展**（PI/NTK/YaRN——最便宜，扩展现有模型的首选）；**稀疏/局部注意力**（滑窗、块稀疏、以及 DeepSeek 后续的原生稀疏注意力方向 NSA/DSA——改变平方复杂度本身，面向原生长上下文训练）；**架构混合**（线性注意力/SSM 混合层——固定状态压缩历史，见交叉基础的注意力题）；**工程外挂**（检索、上下文压缩、分段+记忆——不动模型）。定位：前三条是模型层能力，最后一条是应用层兜底，生产系统通常是"模型层有多长能力 + 应用层仍做管理"的叠加。

:::
