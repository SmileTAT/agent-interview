# MLA 是怎么压缩 KV Cache 的？为什么能不掉点？

<QuestionMeta />

## 题目

多篇 DeepSeek 面经报告此题几乎必问：解释 Multi-head Latent Attention（MLA）的原理——它如何压缩 KV Cache、与 MQA/GQA 的区别，以及为什么压缩后效果反而不差。

::: details 参考答案

**要解决的问题**：自回归推理时 KV Cache 显存随（序列长度 × 层数 × 头数 × 头维度）线性增长，是长上下文与高并发服务的第一瓶颈。MHA 每个头都存独立的 K/V；MQA/GQA 通过让多个 Q 头共享一组（或几组）KV 头来省显存，但共享即削减表达，通常伴随质量损失。

**MLA 的思路：不共享，而是低秩压缩。**

1. **联合低秩压缩**：对每个 token 的隐状态，用一个下投影矩阵压成一个很小的**潜向量 c^KV**（V2/V3 中仅 512 维）——推理时 **KV Cache 里只存这个潜向量**，而不是各层各头的完整 K/V；
2. **按需还原**：计算注意力时用上投影矩阵从潜向量还原出各头的 K 和 V。数学上，K 的上投影可以被吸收进 Q 的投影、V 的上投影可以被吸收进输出投影（矩阵结合律），所以推理时**并不需要真的显式还原**，计算仍然高效；
3. **解耦 RoPE**：RoPE 是位置相关的旋转，直接作用在压缩重建的 K 上会破坏"上投影可被吸收"的数学性质。MLA 的解法是把 K 拆成两部分——**压缩部分不带 RoPE，另设一小段独立的、跨头共享的 RoPE 键**专门携带位置信息，Q 侧对应拼接。缓存里因此存"潜向量 + 小段 RoPE 键"两样东西。

**效果量级**：相对 MHA，KV Cache 缩减到几十分之一（V2 报告约 93% 缩减），逼近 MQA 的缓存开销。

**为什么不掉点**：MQA/GQA 是"砍头数"——强制多个头用同一份 KV，是硬约束；MLA 是"学一个低秩表示"——压缩矩阵是训练出来的，模型自己学习把信息装进潜向量。低秩假设与注意力矩阵的实际冗余相符，因此在 DeepSeek 的消融里 MLA 质量不低于甚至优于 MHA。

**答题关键**：低秩联合压缩 + 缓存的是潜向量 + 上投影吸收 + 解耦 RoPE 四个点齐了才算答透；对比 MQA/GQA 要说出"共享 vs 学习压缩"的本质差异。

:::

## 追问链

::: details 追问 1（面经真实追问方向）：为什么 RoPE 必须解耦？直接对还原后的 K 加 RoPE 不行吗？

行，但会毁掉推理优化：上投影吸收的前提是 K 对 Q 的贡献是**固定线性变换**；RoPE 的旋转角随位置变化，夹在中间后"压缩→旋转→点积"无法合并成一个静态矩阵，每步都得真还原全部 K，压缩省下的显存被计算与带宽开销吃回去。解耦设计把位置信息单独放进一小段共享键，潜向量通道保持"位置无关"，两全其美。这一问答不出来，说明只背了结构没懂推导。

:::

::: details 追问 2：MLA 压缩的是显存，那它对计算量（FLOPs）和吞吐的影响是什么？

分阶段看：解码阶段的瓶颈是**访存**（每生成一个 token 要搬运整个 KV Cache），缓存缩小几十倍直接提升解码吞吐、支持更大 batch——这是主要收益；FLOPs 上潜向量引入了额外的投影计算，但吸收技巧使增量有限，且解码本就是 memory-bound，算力略增不是瓶颈。预填充阶段收益相对小（compute-bound）。所以准确说法是"MLA 用少量计算换大量访存与显存"，方向正对解码瓶颈。

:::

::: details 追问 3：如果让你在自己的模型/业务里借鉴 MLA，你会评估哪些前提？

三个前提：**从头训练或深度改造**——MLA 改变了注意力参数结构，不是推理期插件，已有模型迁移需要转换与继续训练（社区有 MHA→MLA 的迁移工作但有成本）；**瓶颈确实在 KV 显存**——短上下文、小并发的业务收益有限，先量化自己的解码访存占比；**框架支持**——推理引擎要正确实现吸收与解耦 RoPE 路径才能兑现收益。如果只是想省 KV 显存又不想动结构，量化 KV Cache、GQA 微调、滑窗注意力是更轻的替代路线。

:::
