# Agent 和 Workflow 的区别是什么？如何选择？

<QuestionMeta />

## 题目

"Agentic 系统"经常被混用于两类东西：Workflow 和 Agent。请说明两者的本质区别，并给出选型原则。

::: details 参考答案

**本质区别在于"控制流由谁决定"**（参考 Anthropic《Building Effective Agents》的划分）：

- **Workflow**：LLM 和工具被**预定义的代码路径**编排——先做 A 再做 B，分支条件由代码写死。LLM 只在每个节点内完成局部任务（分类、生成、抽取）。
- **Agent**：LLM **自己决定**控制流——下一步调什么工具、要不要继续、何时结束，由模型在循环中动态决策。

常见 Workflow 模式：提示链（prompt chaining）、路由（routing）、并行化、编排者-工作者、评估-优化循环。这些都不是 Agent，但足以覆盖大量生产场景。

**选型原则**：

1. **任务路径可预知 → Workflow**：步骤固定、分支可枚举时，Workflow 更便宜、更快、行为可预测、好测试；
2. **任务路径不可预知 → Agent**：步骤数量和顺序依赖中间结果（排错、调研、开放式任务）时，才值得让模型接管控制流；
3. **从简单开始升级**：先试单次 LLM 调用 → 不够再上 Workflow → 确实需要动态决策再上 Agent。复杂度只在带来可度量收益时才增加。

**答题关键**：能说出"控制流归属"这个判据，并表达"Agent 不是默认选项而是升级选项"的工程克制。

:::

## 追问链

::: details 追问 1：为什么"能用 Workflow 就不用 Agent"？Agent 多出的成本具体在哪？

三块：**不确定性成本**——模型决策有方差，同样输入可能走不同路径，测试和 SLA 都更难做；**token 成本**——Agent 每步都要带上完整上下文重新推理；**排错成本**——失败可能出在任意一步的决策上，归因困难。Workflow 的行为空间是有限的、可穷举测试的，这在生产环境是巨大优势。

:::

::: details 追问 2：实际系统往往是混合的，你会怎么组合两者？

外层用 Workflow 定骨架、内层局部放 Agent：例如客服系统外层是固定路由（分类→分流→兜底），只有"故障排查"这一支内部是 ReAct Agent；或者 Agent 负责规划、Workflow 负责执行已知的标准操作序列。原则是**把自主性限制在真正需要它的最小范围内**。

:::

::: details 追问 3：怎么判断一个任务的"路径不可预知"？给个具体判据。

试着把任务的处理流程画成流程图：如果分支条件能用规则写清楚、深度有限，就是可预知的；如果你发现自己在写"视情况而定""可能要回到上一步"、分支组合爆炸，就是不可预知的。另一个实用判据：让领域专家描述他处理该任务的过程，如果专家自己也说"看情况随机应变"，那就是 Agent 的场景。

:::
