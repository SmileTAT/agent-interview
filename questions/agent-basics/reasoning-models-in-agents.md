# 推理模型和普通指令模型在 Agent 场景下如何选型？

<QuestionMeta />

## 题目

推理模型（如 OpenAI o 系列、DeepSeek R1 及各家的深度思考模式）在 Agent 系统中什么时候值得用？请从能力、成本、延迟角度给出选型思路。

::: details 参考答案

**推理模型的本质**：在输出答案前生成长思维链（test-time compute），用推理时的额外计算换取更强的规划、数学、代码与复杂决策能力，通常经过强化学习（如 RLVR/GRPO 类方法）训练以提升推理质量。

**在 Agent 场景的选型思路——按环节拆分而不是全局二选一**：

| 环节 | 建议 | 理由 |
|------|------|------|
| 任务规划 / 复杂决策 | 推理模型 | 规划错误会被后续所有步骤放大，值得为首步买最强推理 |
| 简单工具调用执行 | 指令模型（甚至小模型） | 按既定计划填参数、调工具不需要深度推理 |
| 排错 / 数学 / 代码修复 | 推理模型 | 可验证反馈 + 深推理是最佳组合 |
| 高频低难度分类 / 路由 | 小指令模型 | 延迟和成本敏感，能力过剩是浪费 |
| 摘要 / 格式化 | 指令模型 | 推理链带来的增益接近零 |

**代价意识**：推理模型的思考 token 也计费且不可见地拉长首 token 延迟——一个规划步可能思考数千 token。同步交互链路（对话机器人）要谨慎；异步任务（深度调研、批处理）更能容忍。

**混合架构是主流答案**：强推理模型做 planner/critic，快模型做 executor，用模型路由按任务难度分发。现代混合推理模型（同一模型可开关思考深度）让这个权衡可以在单模型内通过参数调节实现。

**答题关键**：拒绝"哪个更好"的二元回答，按 Agent 环节拆分 + 明确成本延迟代价。

:::

## 追问链

::: details 追问 1：怎么量化验证"规划环节换推理模型"是否值得？

固定 executor 不变，只切换 planner 模型，在同一评测集上对比：任务完成率、平均步数（好的规划应该减少无效步骤）、端到端成本与延迟。注意用**端到端任务成功率**做主指标而不是规划本身的"看起来合理"——规划质量只能通过执行结果验证。如果完成率提升不足以覆盖成本增幅，就不值得。

:::

::: details 追问 2：推理模型的思考过程要不要放进 Agent 的上下文传给下一步？

一般不放完整思维链：体积大、且思考过程可能包含被否决的中间想法，污染后续步骤。实践是让模型输出**结构化结论**（计划步骤、决策及理由摘要）进入上下文，思维链只落到 trace 日志用于调试和评测。部分 API 对思考内容跨轮传递有专门机制（如加密的推理项），按供应商推荐方式处理即可。

:::

::: details 追问 3：思考预算（thinking budget）怎么设？

按任务难度分层配置而不是全局一个值：路由/简单步给最小预算或关闭思考，规划/排错步给高预算。用评测数据找拐点——多数任务的收益随思考预算增长很快饱和，超过拐点纯烧钱。生产上还要设硬上限防止个别请求思考失控，并监控思考 token 占比作为成本健康度指标。

:::
