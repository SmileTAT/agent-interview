# Reflection（自我反思）机制如何提升 Agent 质量？有什么代价？

<QuestionMeta />

## 题目

解释 Reflection / Self-Critique 模式的工作原理、典型实现方式，以及它的适用边界。

::: details 参考答案

**原理**：让模型对自己（或另一个实例）的输出进行批判性评审，再基于批评意见修订，形成"生成 → 批评 → 修订"的循环。理论依据是：模型**判别错误的能力通常强于一次性生成正确答案的能力**——验证比生成容易。

**典型实现**：

1. **同模型两阶段**：同一个模型先生成，再以"评审者"角色（不同提示）批评自己的输出；
2. **生成-评审分离**：用独立的 critic（可以是更强的模型或带 rubric 的专用提示）评审，generator 修订；
3. **带外部信号的反思**（Reflexion 思路）：不是凭空自评，而是基于**环境反馈**（测试失败信息、工具报错、编译错误）进行反思，把失败原因写入记忆再重试——这是效果最扎实的一类；
4. **周期性反思**：长任务中每 k 步插入"当前进展是否偏离目标"的检查，防漫游。

**代价与边界**：

- 延迟和 token 成本近乎翻倍（每轮多一次评审+修订）；
- **没有外部信号的纯自我反思容易"空转"**：模型可能自我说服、在两个版本间震荡，或把对的改成错的；
- 收益在**有可验证反馈的任务**（代码、数学、有明确 rubric 的写作）上最明显；在开放性任务上收益递减。

**答题关键**：区分"有外部反馈的反思"和"凭空自评"，前者是工程利器，后者要谨慎。

:::

## 追问链

::: details 追问 1：反思循环怎么终止？会不会无限修订？

三种终止条件组合：**通过判据**（测试全绿、critic 给出通过评级）、**轮次上限**（通常 2~3 轮，边际收益快速递减）、**收敛检测**（两轮输出差异极小或在版本间震荡时停止，取评分最高的版本）。工程上一定要有轮次上限兜底，并记录每轮版本便于回溯。

:::

::: details 追问 2：critic 和 generator 用同一个模型，评审会不会"偏心"？

会，这是自我偏好偏差：模型倾向认可自己风格的输出。缓解手段：给 critic 一份**具体的、可核对的 rubric**（检查项而非整体感觉）；critic 提示中不给出"这是你自己写的"信息；关键场景用不同模型或更强模型做 critic；用外部可验证信号（测试、静态检查）替代主观评审。

:::

::: details 追问 3：推理模型内置了自我修正，还需要显式的 Reflection 结构吗？

推理模型在思维链内部确实会自我检查，简单任务上显式 Reflection 的收益缩小了。但两者不冲突：思维链内的修正**看不到外部反馈**，而工程上最有价值的反思恰恰是"跑了测试/调了工具之后基于真实结果的反思"，这仍需要显式的循环结构。另外显式 Reflection 的中间产物（批评意见）可观测、可评测，这对生产系统是额外价值。

:::
