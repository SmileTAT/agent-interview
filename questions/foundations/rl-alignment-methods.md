# SFT、RLHF、DPO、GRPO 的区别是什么？和 Agent 能力有什么关系？

<QuestionMeta />

## 题目

作为 Agent 应用工程师，需要理解模型是怎么被训出来的。请简明对比 SFT / RLHF / DPO / GRPO，并说明它们与 Agent 能力的关系。

::: details 参考答案

**一句话版本**：

- **SFT（监督微调）**：拿高质量示范数据直接模仿学习——"照着标准答案抄"。教会格式、指令遵循和基本能力，是后训练的第一步；
- **RLHF**：人类对输出排序 → 训练奖励模型 → 用 PPO 等 RL 算法让策略最大化奖励——"训练一个品味打分器，再照着它优化"。能学到超越示范的偏好，但流程重（四个模型、训练不稳、算力大）；
- **DPO（直接偏好优化）**：跳过显式奖励模型与 RL 循环，直接在偏好对（chosen/rejected）上用一个闭式损失优化策略——"把 RLHF 简化成一个监督式损失"。工程简单稳定，是开源社区偏好对齐的主流；离线数据、表达力上限低于在线 RL；
- **GRPO（组相对策略优化，DeepSeek 提出）**：PPO 的简化变体——同一提示采样一组回答，用**组内相对优劣**（各回答奖励减组均值）作为优势信号，省掉 PPO 的价值网络（critic），显存与实现大幅简化。配合**可验证奖励（RLVR）**——数学对不对、代码过不过测试这类客观信号——成为训练推理模型（R1 类）的代表性方法。

**与 Agent 能力的关系（应用工程师该懂的部分）**：

1. Agent 依赖的核心能力——多步推理、工具调用格式的可靠性、"知道何时停"——主要来自后训练阶段，尤其是 **RLVR 类训练**（在可验证任务上做 RL）催生的推理与 agentic 能力；
2. 前沿方向是**agentic RL**：直接在多轮工具使用环境里训模型（奖励=任务完成），模型不只是会"答"，而是被训过"做"；
3. 实用含义：选型时关注模型是否针对工具使用/agentic 场景做过专门后训练（各家的 agentic 基准分数），比通用聊天分数更能预测 Agent 表现。

**答题关键**：四者的一句话机制对比 + GRPO 与 RLVR 的搭配 + "Agent 能力来自后训练"这个应用层结论。

:::

## 追问链

::: details 追问 1：为什么可验证奖励（RLVR）这么关键？

因为 RL 的上限由奖励信号质量决定。人类偏好奖励（RLHF）是主观、有噪声、可被"讨好"（模型学会写得自信漂亮而非正确——reward hacking）；可验证奖励（答案对错、测试通过、编译成功）客观且不可讨好，模型只能靠真的提升推理来拿分——这是推理能力在数学/代码上率先突破的原因。局限也在这：**难以验证的领域（开放写作、主观判断）RLVR 无从下手**，如何把"可验证"扩展到更多领域是当前的核心研究方向。

:::

::: details 追问 2：DPO 比 RLHF 简单这么多，为什么大厂前沿模型还在用在线 RL？

DPO 是离线方法：只能从固定的偏好数据集学习，策略变化后数据分布就过时了（off-policy 漂移）。在线 RL（PPO/GRPO 类）在训练中不断用**当前策略**采样并获取奖励，能持续探索到数据集之外的更优行为——推理能力的"自我进化"（越训越会想）本质上依赖这种在线探索。经验规律：资源有限、目标是偏好对齐 → DPO 够用；追求能力上限（尤其推理/agentic）→ 在线 RL。

:::

::: details 追问 3：作为应用工程师，这些知识怎么影响你的日常决策？

至少四处用得上：**模型选型**——看模型卡时理解"经过 agentic 后训练/RLVR 训练"意味着什么，用对应基准对比；**失败归因**——工具调用格式老出错更可能是模型后训练不足，换模型比堆提示有效；**提示策略**——推理模型（RL 训出的长思维链）不需要你再手写"一步步思考"，过度指挥反而干扰；**数据飞轮意识**——你的产品积累的成功轨迹与用户反馈，正是将来微调/RL 的原料，日志设计时留好（质量标注、轨迹完整性）。

:::
