# 多轮对话的历史消息应该怎么管理？全量保留还是删减？

<QuestionMeta />

## 题目

对话式 Agent 随着轮次增加，历史消息不断累积。请对比常见的历史管理策略及适用场景。

::: details 参考答案

四种基本策略，实践中常分层组合：

**1. 全量保留**
简单、信息无损、对 KV 缓存最友好（纯追加）。短会话（客服平均十几轮）的默认选择——**不要过早优化**，很多系统根本到不了需要删减的长度。

**2. 滑动窗口（保最近 N 轮）**
实现简单，但会"失忆"：窗口外的用户偏好、早期约束直接消失，用户体验是"它忘了我开头说的话"。只适合轮次间弱关联的场景（工具型问答）。

**3. 滚动摘要（窗口 + 摘要）**
超出窗口的部分压缩成摘要保留在上下文头部，近期轮次保持原文。兼顾长度与记忆连续性，是长对话的主流方案。代价：摘要有信息损失、摘要更新会打断缓存前缀（更新频率要克制）。

**4. 选择性保留（重要性过滤）**
按消息类型区别对待：用户的约束与偏好长期保留，工具的大段返回用完即可压缩，闲聊可丢弃。效果最好但复杂度最高，需要定义重要性规则甚至用模型打分。

**组合范式**（长对话推荐）：`系统提示 + 持久要点（用户约束/偏好，结构化维护） + 滚动摘要 + 最近 N 轮原文`。

**选型判据**：先测你的真实会话长度分布——P95 都打不满窗口就用全量；确认需要删减时，优先保证"用户说过的约束不丢"，这是体验底线。

**答题关键**：不过早优化 + 四策略的取舍 + 组合范式 + "约束不丢"的底线意识。

:::

## 追问链

::: details 追问 1：工具调用的中间消息（调用+返回）在历史里要保留多久？

工具消息是历史膨胀的主力，但淘汰要分对待：**返回内容**（大段检索结果、文件内容）在被消化成结论后就可压缩为一行占位（"第3轮检索了X，要点已纳入结论"）；**调用记录本身**（调了什么、成败）保留更久——它防止模型重复调用、支持"之前查过了"的判断。注意成对处理：删返回不删调用时，部分 API 会因消息不配对报错，压缩时要保持结构合法。

:::

::: details 追问 2：用户在第 3 轮说"我对花生过敏"，第 40 轮推荐了花生菜品。怎么系统性防止这类事故？

这类"约束丢失"不能指望摘要碰运气，要**结构化提取**：识别用户消息中的持久约束（过敏、预算、禁忌、偏好），写入独立的会话要点区（或长期记忆），每轮都注入且不参与滚动淘汰。摘要是有损压缩，约束是无损白名单——两条通道分开。评测上专门构造"早期约束、晚期考验"的用例盯住这个指标。

:::

::: details 追问 3：历史管理策略上线后，怎么知道它没有伤害体验？

三个信号源：**评测**——长对话用例集（含回马枪用例）上策略 A/B 的完成率与约束遵守率；**线上行为指标**——用户重复陈述率（"我刚才说过"类消息占比）、纠正率、长会话的满意度与短会话的差值；**成本指标**——平均 token/轮、缓存命中率。理想状态是成本下降而重复陈述率不升；若用户开始频繁重复自己，说明删减策略切到了体验的肉。

:::
