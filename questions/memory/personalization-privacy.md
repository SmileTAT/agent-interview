# 跨会话个性化怎么做？隐私边界在哪里？

<QuestionMeta />

## 题目

基于长期记忆的个性化能显著提升体验，但也带来隐私与信任问题。请谈谈个性化的实现层次和你认为应有的隐私设计。

::: details 参考答案

**个性化的三个层次**（由浅入深）：

1. **显式偏好应用**：用户明说的设置与约束（语言、格式偏好、预算），最安全，照做即可；
2. **交互习惯适配**：从历史交互归纳的模式（喜欢简洁回答、常在周五做周报），属于合理推断，应可被用户看见和纠正；
3. **深度画像推断**：从行为推断用户未明说的属性（健康状况、财务水平、情感状态），**价值和风险都最大**，默认不做或严格限制使用场景。

**隐私设计的核心原则**：

- **透明**：用户能看到系统记住了什么（"我的记忆"界面），个性化行为可解释（"因为您之前提到过X"）；
- **可控**：可编辑、可删除单条记忆，可整体关闭个性化；删除要真删（含向量库中的衍生数据），这也是 GDPR 类法规的硬要求；
- **最小化**：写入门槛 + 敏感类别（健康/宗教/政治/性取向等）默认不记，即使用户提及；
- **用途限定**：记忆只用于服务该用户本人，不得用于跨用户分析或营销，跨 Agent 共享按领域授权（见记忆共享问题）；
- **惊讶最小化**：一个实用判据——如果 Agent 说出某条记忆会让用户惊讶或不适（"你怎么知道这个"），说明越界了。宁可让用户重复一次，不要让用户后背发凉。

**答题关键**：个性化分层（越深风险越大）+ 透明/可控/最小化三支柱 + "惊讶最小化"的产品直觉。

:::

## 追问链

::: details 追问 1：用户说"帮我记住我老板叫张三，脾气不好"——这是关于第三方的信息，记不记？

这是记忆系统最微妙的边界之一：用户有正当需求（写邮件时注意措辞），但被记录者没有同意。可行的折中：记录为**用户的主观工作备注**（归属用户、服务用户），而非关于张三的客观事实；不做第三方画像聚合（不允许跨用户拼出"张三"的档案）；敏感评价类内容加短时效。原则：记忆的主体永远是"用户的表达"，不是"第三方的属性"。

:::

::: details 追问 2：技术上"真删除"难在哪？

难在衍生数据的扩散：原始条目删了，但它可能已进入向量库的 embedding、会话摘要、抽取出的其他事实、模型微调数据、日志与备份。工程要求：记忆数据全链路带溯源 ID，删除时级联清理衍生物；日志与备份设定期滚动过期；严禁把含个人记忆的数据混入训练集（或建立可撤回的数据管理）。"删除"应该是设计初期的架构需求，事后补几乎不可能干净。

:::

::: details 追问 3：个性化的收益怎么证明？万一用户其实不想要呢？

别假设，用实验：个性化开/关的 A/B，看任务完成效率（少问了多少轮）、留存、满意度；同时监控负信号——用户关闭个性化的比例、删除记忆的频率、"你怎么知道"类反应。行业经验是**浅层个性化（层次1-2）收益稳定且负反馈少，深层推断收益边际但风险陡增**。所以优先做透显式偏好的应用，深层推断留给有明确场景论证的少数功能。

:::
