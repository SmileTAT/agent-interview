# 记忆检索的时机和策略：什么时候查、查什么、注入多少？

<QuestionMeta />

## 题目

有了长期记忆存储后，"什么时候检索、拿什么当查询、注入多少条"直接决定记忆系统的实际效果。请说明设计方案。

::: details 参考答案

**检索时机——三种模式**：

1. **会话启动时预取**：加载用户核心画像（稳定偏好、关键约束），作为"常驻记忆"放进上下文。适合小而稳定的核心事实；
2. **每轮自动检索**：拿当前用户消息做查询，自动召回相关记忆注入。覆盖面广，但每轮都有检索成本和噪音风险；
3. **模型主动检索（记忆即工具）**：把 `search_memory` 做成工具，模型觉得需要时自己查。精准、省预算，但依赖模型"意识到自己该查"——它不知道记忆里有什么，可能想不起来查。

**主流组合**：核心画像预取常驻 + 记忆工具供主动查询；对话型产品再加轻量的每轮自动检索。

**查询构造**：直接拿用户原话做向量查询效果一般（口语化、指代多），改进：用改写后的语义查询（结合对话上下文补全指代）；结构化记忆走字段过滤而非向量（查"预算"就按 key 取）；情景记忆检索时带时间与领域过滤。

**注入策略**：

- **限量**：top-k 加相关性阈值，宁少勿多——不相关的记忆注入是负收益（误导模型"用户可能想要这个"）；
- **注入位置**：作为独立的记忆区块（标明"以下是历史记忆，可能过时"），不伪装成对话历史；
- **带元信息**：时间戳、置信度，让模型能正确地打折使用。

**答题关键**：三种时机的组合设计 + 查询改写 + "少而准 + 带元信息"的注入纪律。

:::

## 追问链

::: details 追问 1：检索到的记忆和用户当前说的矛盾（记忆说喜欢靠窗，这次说要靠过道），模型有时会"过度尊重记忆"，怎么办？

优先级规则要显式：注入的记忆区块头部写明"当前对话中的用户表述永远优先于历史记忆"。同时这是记忆更新的触发点——检测到冲突时把新偏好写回（更新或标记情景例外："商务出行时偏好过道"）。评测集中构造"记忆与当前意图冲突"的用例，把"当前优先"的遵守率作为记忆系统的固定回归项。

:::

::: details 追问 2：每轮自动检索会不会让 Agent 变"自作聪明"——总把不相关的历史扯进来？

会，这是自动检索的典型副作用，根因是**相关性阈值过松 + 模型对注入内容的过度响应**。治理：提高阈值宁可漏检（漏了还有记忆工具兜底）；注入措辞去指令化（"供参考的背景"而非"请考虑以下信息"）；监控"记忆引用恰当率"——抽样评审模型引用记忆的场合是否真的合适。体验上"偶尔忘事"比"总翻旧账"伤害小，阈值该往保守调。

:::

::: details 追问 3：记忆检索的效果怎么量化？

分层评：**检索层**——构造（对话上下文，应召回的记忆条目）标注集，测 recall/precision；**行为层**——端到端用例：需要历史记忆才能答对的任务的完成率（如"订上次那家酒店"）；**体验层**——线上的用户重复陈述率、"你还记得吗"类问题的答对率、记忆相关的用户纠正次数。另外盯成本：每轮检索的延迟与注入 token 开销，防止记忆系统变成隐性的性能税。

:::
