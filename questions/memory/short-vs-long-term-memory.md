# Agent 的短期记忆和长期记忆分别指什么？怎么实现？

<QuestionMeta />

## 题目

请解释 Agent 记忆系统的分层：短期记忆与长期记忆各自的范围、实现方式和设计要点。

::: details 参考答案

**短期记忆（工作记忆）= 当前会话的上下文窗口内容**

- 范围：本次任务的对话历史、工具调用与观察、中间结论；
- 实现：就是上下文管理本身（滑动窗口、滚动摘要、结构化笔记），生命周期随会话结束而结束；
- 设计要点：见上下文工程主题——它解决"这次任务内不忘事"。

**长期记忆 = 跨会话持久化的信息**，又分三类（借认知科学的划分）：

| 类型 | 内容 | 典型实现 |
|------|------|---------|
| 语义记忆 | 关于用户/世界的事实：偏好、过敏、项目背景 | 结构化存储（用户画像表）或向量库 |
| 情景记忆 | 过去的交互经历：上次讨论了什么、某任务的处理过程 | 会话摘要归档 + 向量检索 |
| 程序记忆 | "怎么做"的经验：任务套路、踩坑教训、成功策略 | 沉淀为提示规则/技能文档/few-shot 库 |

**长期记忆的完整链路是"写入 → 存储 → 检索 → 注入"四步**，每步都有设计决策：写入（何时提取什么，见"存什么"一题）、存储（结构化 vs 向量）、检索（何时检索、检索什么，见"检索时机"一题）、注入（放入上下文的哪个位置、带多少条）。

**关键认知**：模型本身是无状态的，所谓"记忆"全部是**工程系统在模型外部实现的**——记忆系统的质量取决于这条链路的工程设计，而不是模型能力。

**答题关键**：短期=上下文管理、长期=四步链路 + 三类记忆的划分和各自的实现形态。

:::

## 追问链

::: details 追问 1：长期记忆用向量库还是结构化存储？

按信息形态分：**有明确 schema 的事实**（偏好、生日、配置）用结构化存储——精确读写、可更新可删除、注入时干净；**开放式的经历与文本**（历史会话、讨论内容）用向量检索——无法预知查询模式，语义检索兜底。实践是混合：结构化画像 + 向量化情景归档。常见错误是全部塞向量库，结果"用户预算是多少"这种该精确回答的问题变成了模糊检索。

:::

::: details 追问 2：记忆过时了怎么办？比如用户三个月前说"预算 5000"，现在变了。

三个机制：**带时间戳**——所有记忆记录写入时间，注入时附带（"用户于 4 月表示预算 5000"），让模型知道信息的新鲜度；**冲突更新策略**——新信息与旧记忆冲突时更新而非并存（结构化存储的优势），向量库则需要显式的失效标记；**衰减与确认**——关键决策依赖旧记忆时，提示模型向用户确认而不是直接采用（"您之前提到预算 5000，现在还是这个范围吗？"）。

:::

::: details 追问 3：程序记忆（经验教训）怎么落地？听起来最玄。

最可操作的形态是**反馈驱动的规则沉淀**：任务失败后归因，把教训写成可执行的规则或检查项，存入按任务类型索引的经验库，同类任务启动时检索注入；成功的解法模式沉淀为 few-shot 示例或技能文档（如"处理 X 类工单的标准步骤"）。要点是有淘汰机制——定期评测每条经验规则是否还带来收益，避免经验库变成过时补丁堆。这本质上是把"组织知识管理"做进 Agent 系统。

:::
