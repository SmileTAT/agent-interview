# 长期记忆应该存什么：原始对话还是提炼后的事实？

<QuestionMeta />

## 题目

会话结束后要把什么写进长期记忆？直接存原始对话，还是让模型提炼成事实？请分析两种路线及写入时机的设计。

::: details 参考答案

**存原始对话（归档路线）**：

- ✅ 无损，未来任何问题都能回查；实现简单（切块入向量库）；
- ❌ 检索质量差——对话是低密度、口语化、指代混乱的文本，向量检索经常召回大段无关闲聊；注入时占空间且模型还要现场重新理解一遍。

**存提炼事实（抽取路线）**：

- ✅ 高密度、可直接使用（"用户对花生过敏"一条顶三轮对话）；结构化后可精确更新、去重、解决冲突；
- ❌ 有损——抽取时判断"不重要"的信息永久丢失；抽取本身可能出错（误解、过度概括），错误会被长期继承。

**实践答案：双层并存**。

- **事实层**：会话结束（或进行中实时）用模型抽取结构化记忆条目（偏好/约束/事实/待办），作为检索与注入的主通道；
- **归档层**：原始对话降冷存储，作为事实层的溯源与兜底——事实存疑时可回查，抽取规则升级后可对归档重放重建事实层。

**写入时机**：会话结束批量抽取（简单，主流），关键信息实时写入（用户明确说"记住X"时不等会话结束），周期性整理（合并重复、消解冲突、淘汰过期——记忆系统的"垃圾回收"）。

**写入门槛**：不是什么都值得记。设显著性判据（用户显式陈述的偏好/约束 > 反复出现的模式 > 一次性细节），宁缺勿滥——低质量记忆会在未来的每次检索中制造噪音。

**答题关键**：双层架构（事实层主用、归档层溯源）+ 写入门槛意识 + 记忆需要"垃圾回收"。

:::

## 追问链

::: details 追问 1：抽取出错（比如把"我朋友对花生过敏"记成"用户对花生过敏"）怎么办？

三道防线：抽取时保留**溯源引用**（记忆条目挂原始对话位置，可回查验证）；关键类记忆（健康、财务）注入时标注置信度并要求使用前确认；提供用户可见的"我的记忆"管理界面，允许查看、修正、删除——这既是纠错通道也是隐私合规要求。根治靠抽取评测集：拿标注好的对话样本持续回归抽取质量，重点盯指代消解和主体归属错误。

:::

::: details 追问 2：记忆越攒越多，检索噪音变大，"垃圾回收"具体怎么做？

周期性维护任务做四件事：**去重合并**（同一事实多次记录合并为一条并提升置信度）、**冲突消解**（保留最新+标记历史）、**过期淘汰**（时效性记忆如"下周要出差"过期即删）、**使用率降权**（长期未被检索命中的条目降权或归档）。频率上用户级每周/每月即可。这套机制的价值经常被低估——没有 GC 的记忆系统会在几个月内退化成噪音库。

:::

::: details 追问 3：多个 Agent 共享一个用户的记忆，会有什么问题？

三个问题：**语境错位**——购物 Agent 记的"喜欢简洁"被编程 Agent 理解成"代码不要注释"；**写入污染**——一个低质量 Agent 写入的错误事实影响所有 Agent；**权限与隐私**——健康助手记录的敏感信息不该被营销 Agent 读到。设计上：记忆条目带来源 Agent 和领域标签，检索按领域过滤；写入按 Agent 分级信任；敏感类别做访问控制。共享记忆本质是个多租户数据产品，不只是一张公共表。

:::
